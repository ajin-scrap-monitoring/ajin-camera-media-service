# 남은 운영 검증

2026-10-27 종료 날짜의 MP4 자동 준비·검증·원본 전환을 구현했다. 하루 전체 다운로드는 기존 MP4를 전송하고, 이벤트는 오늘 TS 또는 보관 MP4에서 요청 구간을 스트림 복사한다. API 경로는 유지되며 exports POST는 준비 상태 확인용이다. 보관 기간은 기존 정책(기본30일)을 따르고24시간 캐시 만료는 제거했다. 배포·검증 결과는 VALIDATION.md에 기록한다.

같은 날 운영 이미지f4cc08f를 배포하고 자동 전환을 활성화했다. 서버 전체204개 시험과 실제 백엔드 접근·HLS·오늘 이벤트 추출은 통과했다. 기존2026-10-26의 약16.6시간 영상은 최초 자동 준비/검증 중이다. 이 대용량 파일이ready로 전환된 뒤 실제 운영 MP4 직접 다운로드·TS 정리 후 HLS/과거 이벤트 추출을 추가 확인해야 한다. 자동 시험에서는 해당 전환을 검증했다. 운영 첫 파일 완료와 시험 통과를 구분한다.

2026-10-26 이벤트 시각 기반 구간 추출(`event_at`)을 main/GitHub와 운영 미디어서버에 반영했다. 실제 서버 이미지 전체165개 테스트와 운영 녹화의400/404/409, 과거 부족·미래 꼬리 부분 추출, MP4 디코딩, Range·중복·삭제를 검증했다. 기존 백엔드 컨테이너에서 미디어서버 API 접근200도 확인했다. 상세는 VALIDATION.md와 BACKEND_API_CONTRACT.md의5.1절을 참조한다.

새 재인코딩 없는 추출을 사용하려면 백엔드 담당자가 이벤트 요청에 `event_at`을 보내야 한다. 생략한 기존 요청은 기존 수집·인코딩 방식이다. 대시보드의 부분 구간·누락 시간 표시와 현장 장비 장기 검증은 여전히 남아 있다.

2026-10-14 날짜 녹화 기능을 추가했다. 날짜 목록, 오늘/지난 날짜 HLS, 실제 누락, 단일 MP4 준비, 삭제·만료와 용량 제한은 자동 테스트 대상이다. 실제 서버 검증 결과는 [VALIDATION.md](VALIDATION.md), 동료 연동 규격은 [DAILY_RECORDING_API_GUIDE.md](DAILY_RECORDING_API_GUIDE.md)에 기록한다. 실제 장비의24시간 처리량·저장량과 상대 백엔드/대시보드 연결은 별도 확인이 필요하다.

2026-10-15 기존 운영8889 서비스를 날짜 녹화 버전으로 교체하고 기능을 활성화했다. 입력 camera-main과 영구 저장소를 유지했다. 누락이 수천 건일 때 공용 저장 처리를 막는 집계/조회 문제를 수정했다. 저장 예산32GiB/최소 여유5GiB 안에서 운영하며 실제30일 분량은 용량 산정이 필요하다. 운영 교체를 위한 부하 분리로 합성24시간 시험을 일시 중단했으며 무중단 성공으로 보고하지 않는다.
