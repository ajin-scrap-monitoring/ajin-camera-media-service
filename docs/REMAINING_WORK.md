# 남은 운영 확인

2026-11-06 운영 이미지는 `ajin-camera-media-service:86da053`이다. 기존 SD·원래2GiB 디스크 버퍼에서10분 실제 입력·동시 다운로드 시험을 진행했고 새 수신 큐·저장 오류는0건이었다. 확보된 JPEG를 지연만으로 버리는 처리와 메타데이터 병목을 수정했다. 전체 영상 공백 해결 판정은 아래 미확인 사항 때문에 보류한다. 최신 검증은 [회신](INTEGRATION_REPLY_2026-11-06.md)과 [VALIDATION.md](VALIDATION.md)를 따른다.

- LC-4는 전체 해결 판정 보류다.11/06 최종10분 관찰에서5.921초의 수신시각 공백1건과 직후1초200프레임 수신을 확인했다. 큐·저장 손실은 없지만 엣지·네트워크·서버 이벤트 루프 중 지연 위치는 아직 분리하지 못했다. 다음 조사에서는 엣지 전송 시각과 서버 수신/이벤트 루프 지연을 함께 측정해야 한다. 원본 촬영 시각을 추정해 채우지 않는다.11/03에 관측한 보관 HLS 최초 요청3.0~5.5초 지연의 개선 여부도 별도 확인 대상이다.
- 호스트 전체 재부팅, 전원 장애, SD 카드 내구·장기 디스크 고갈은 별도 운영 검증 대상이다. 저장소 사전 확인과 서비스 시작 단위는 enabled/active이며 서비스만 재시작했다.
- 최종 짧은 성능 관찰이 장시간 무공백 보장은 아니다. 시뮬레이터 생성 시각은 입력에 없으며 수신/전달과 독립적으로 생성 공백을 판정할 수 없다. 과거 손실·유지보수 공백은 복구된 것으로 표시하지 않는다.
- 보관30일은 현재 나이 정책이며 약64GB 카드에30일분 영상을 보장하지 않는다. 실제 생성량·카메라 수·동시 사용자·추출 빈도에 맞춘 용량/매체 계획이 필요하다. 미만료 영상을 공간 확보 때문에 임의 삭제하지 않는다.
- 전체 저장 예산은 애플리케이션 접수·완료 검사다. 파일시스템 하드 쿼터와 오래된 메타데이터 자동 압축/정리는 제공하지 않는다.
- 백엔드 업무 처리와 실제 대시보드 UI 전체 검증은 해당 담당 범위다. 미디어서버가 백엔드 API를 호출하는 기능은 필요하지 않다.
- 선택 썸네일은11/05 구현·배포했다. 원본 프레임 생성 시각은 현재 입력에 없으므로 미지원이다. 촬영 시각을 수신 시각으로 대신 표시하지 않는다. 기존 media-info의 썸네일 unsupported 호환 응답과 별도 thumbnail-info API를 구분한다.
- LC-5 라이다 시뮬레이션 배치·좌표·설정 일관성은 오케스트레이션/라이다 담당 범위다. AI 분석은 이번 요청에 포함하지 않는다.

완료된 항목을 다시 구현하거나 SSD 원본을 정리하는 작업은 남은 과제로 간주하지 않는다. SSD 원본은 삭제하지 않은 안전 보존본이며 SD에서 발생한 새 녹화·삭제 상태 위에 덮어쓰면 안 된다.
