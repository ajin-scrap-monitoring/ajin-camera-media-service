## 수정 범위

영상 정보 캐시는 전용 worker 연결에서 주 녹화 잠금 밖으로 분리했다. 주 DB의 실행 중 커밋도 기존 FULL 내구성을 유지하며 비동기로 완료를 기다린다. 보관 매핑은64개씩 나눠 저장하고 모든 매핑이 완료된 뒤 작은 트랜잭션에서만 MP4 ready를 게시한다. 재시작 전의 일부 매핑은 원본 TS를 유지한 채 재시도한다.

보관 FFmpeg의 파일 입력 속도를8배속으로 제한하고, 녹화 큐·지연이 쌓이면 시작을 보류하거나 Linux 소유 프로세스를 일시 정지한다. TS 정리는64개씩 진행하며 압박 시 양보한다. 공간 회수가 필요한 오류 상태에서는 검증된 MP4의 중복 TS를 소량씩 정리할 수 있어 회복이 영구 차단되지 않는다. 큐1,200프레임·96MiB 및 디스크 JPEG 버퍼2GiB, 기존 저장 예산·미만료 영상 정책은 유지한다.

내부 진단에는 프레임 한도/바이트 한도/단일 입력 초과, 큐 최대치, metadata_commit, archive_merge/verify/mapping, event_loop_lag, receipt_time_gap을 추가했다. 공개 gap reason_code는 그대로이며 확인되지 않은 공백을 다른 원인으로 다시 분류하지 않는다.

8배속은 녹화 우선의 절충이다.24시간 분량의 merge와 전체 decode 검증을 합치면 최소 약6시간이 필요할 수 있고 부하 대기로 늘어날 수 있다. 준비 중에는 TS/HLS를 제공한다. 다운로드 클릭에서 인코딩을 시작하는 구조로 되돌리지 않았다.

## 과거 구간 복구

보존한14:01 KST 카탈로그의2,954개 공백을 현재 저장소와 대조했다. 당시 원본 JPEG, 미완료 조각, 미등록 TS는 남아 있지 않았다. 기존 ready TS와의149개 교차는 최대0.000992초로 밀리초 문자열 경계 차이였으며 실질적인 복구 원본은 확인되지 않았다. 오래된 ffconcat 목록 파일은 영상 픽셀 원본이 아니다.

따라서 **현재 미디어 저장소에서 확인한 원본으로는 해당 과거 구간을 재처리할 수 없다.** 기존 영상·카탈로그 공백을 삭제하거나 다른 프레임을 복제하지 않았다. 외부에 별도 원본이 있는지는 이번 확인 범위에서 입증하지 못했다.

요청서와 같은08:17:10 KST cutoff도 다시 계산했다.2,920개 공백 합355.073초, 재생 길이29,481.266656초로 일치했다. native 시각의 실제 확보 구간 합은29,474.921760초여서 재생 길이와6.344896초 차이가 있다. 인코더는 구간 길이를15fps의 정수 프레임 수로 올려 저장하므로 재생 길이와 수신시각 구간 합은 동일한 값이 아니다. 밀리초 문자열 경계와 native 시각의 나머지 차이는 전체 약5.2ms다. 이 차이를 추가 촬영 손실로 합산하지 않는다.

## 판정의 한계

UNKNOWN_CAPTURE_LOSS 전체의 원인이 확인됐다고 보고하지 않는다. 새 계측으로 서버 이벤트 루프 지연과 수신시각 공백을 함께 대조해야 한다. 원본 카메라 촬영 시각은 입력에 없으며 서버 수신 시각을 촬영 시각으로 바꿔 표시하지 않는다.

정상 입력이 하루 전체 보존되는지의24시간 실측은 짧은 시험·시계 이동 시험과 구분한다. 과거에 없어진 원본은 코드 수정으로 복원되지 않는다. 미디어 내부 API 접근 시험은 백엔드 중개·인증 게이트웨이·실제 프론트 화면 전체 통합 시험과 구분한다.
