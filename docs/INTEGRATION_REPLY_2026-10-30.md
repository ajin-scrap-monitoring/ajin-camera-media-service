# 연동 요청 회신 초안

요청하신 미디어 담당 항목을 수정하고 [PR #1](https://github.com/ajin-scrap-monitoring/ajin-camera-media-service/pull/1)을 main에 병합해 운영 서버 배포까지 완료했습니다. 운영 점검 중 발견한 아카이브 공간 예약 중복 계산과 대용량 faststart I/O 문제도 [PR #2](https://github.com/ajin-scrap-monitoring/ajin-camera-media-service/pull/2)로 수정·병합했습니다. 현재 운영 이미지는 `ajin-camera-media-service:f4019cb`이며 자동 MP4 보관도 활성화했습니다. 후속 수정의 전체289개 시험과 GitHub CI, 운영 서버 시스템 FFmpeg를 사용한50개 회귀 시험을 통과했습니다. 한국 시간2026-10-31 실제 백엔드 컨테이너에서 신규 API 접근과 영상 생성·조회·삭제도 검증했습니다. 요청·응답 예시와 오류 처리는 INTEGRATION_HANDOFF_2026-10-30.md에 정리했습니다.

- **R-10:** 날짜 중복 정리를 직렬화하고 사라진 폴더는 성공 처리하도록 수정했습니다. 실제 권한/I/O 실패는503을 유지합니다. 상세의 cleanup_state로 논리 삭제와 파일 정리 완료를 구분할 수 있습니다. 최초·재삭제·부분 실패 재시도·경합을 검증했습니다. 물리 블록 반환은 단정하지 않으며 space_reclaimed는null입니다.
- **R-07:** 기존 POST /api/v1/clips에 요청별 start_at/end_at을 추가했습니다. 최대1시간이며 공통 정책을 바꾸지 않습니다. 부족한 과거·미래 꼬리는 확보분과 누락 사유로 반환합니다. 오늘 TS/보관 MP4에서 재인코딩 없이 추출하고 실제 절단 시각·바이트 크기·상태·실패 재시도·중복·보관·삭제 규칙을 제공합니다. HLS 재생·목록만으로 파일을 자동 생성하지 않고 다운로드 때만 요청하면 됩니다.
- **R-01:** GET /api/v1/cameras/{camera_id}/status를 추가했습니다. 현재 연결의 프레임 수신 근거로 healthy/interrupted/unknown, 마지막 수신·평가·유효 시각과 사유를 반환합니다. 최대5초 유효하며 재연결/재시작 때 이전 정상 상태를 재사용하지 않습니다. 수신 상태이며 화질·하드웨어 자체 진단은 아닙니다.
- **R-08:** 클립/날짜 media-info 조회에서 실제 파일의 codec·해상도·명목fps·크기를 설정값과 구분해 제공합니다. 날짜 형식 혼합은 측정 범위와 함께, 확인 못한 값은null/unknown으로 반환합니다.
- **R-09:** 현재 입력에 원본 촬영 시각이 없어 제공 불가입니다. 서버 수신 기준과 촬영 시각·동기화 정보의 미지원을 응답에 명시했습니다.
- **R-11:** 선택 썸네일은 이번에 미지원이며 경로/대표 시각은null입니다.
- **R-02·R-03:** 실제 LiDAR 좌표·방향·평면·보정 정보는 센서/현장 담당자 확인이 필요합니다. 미디어 측에서 추정하거나 공개 저장소에 실제 값을 넣지 않았습니다.

미디어 API는 기존 내부 통신 방식으로 운영 중입니다. 사용자 인증과 브라우저의 인증된 다운로드 경로는 백엔드 게이트웨이에서 연결해주시면 됩니다. 기존 event_at 호출은 유지하며, 실제 백엔드 컨테이너에서 오늘 TS/보관 MP4 구간 추출·Range·메타데이터·삭제 응답을 확인했습니다. 업무 처리·대시보드 전체 흐름은 백엔드 측 연동 검증을 진행하면 됩니다.

대용량 기존 날짜 MP4의 전체 디코딩 안전 검증은 현재 백그라운드에서 진행 중입니다. 이 단계와 동시에 새 녹화 증가·실제 백엔드 API 응답을 확인했습니다. 검증 완료 전 원본 TS는 유지하며, 앞선 공간 부족 때 누락된 구간은 복구됐다고 표시하지 않습니다. 하루 전체 다운로드는 이미 준비된 MP4를 그대로 전송하며, 운영 파일7,555,827,783바이트의 HEAD200/Range206와 요청 전후 크기·수정 시각 불변을 확인했습니다.
