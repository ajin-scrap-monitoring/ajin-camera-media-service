# 이벤트 시각 기반 녹화 구간 추출

사용자가 승인한 규칙: 기준 시각에 영상이 없으면 오류, 기준 시각이 미래면 오류, 전후에 없는 과거와 미래는 확보된 영상까지만 제공한다. 중간 누락은 명시하고 수신됐지만 처리 중인 영상은 409로 구분한다. 재인코딩 없이 추출하며 요청 구간을 포함하도록 경계에 최대 1초를 추가할 수 있다.

## 접근 및 호환성

JPEG를 이벤트마다 재인코딩하는 대신 기존 날짜별 H.264/TS 조각을 스트림 복사한다. 전체 JPEG 재인코딩은 대기 원인을 유지하므로 새 기능에서 사용하지 않는다. `POST /api/v1/clips`에 선택 필드 `event_at`(UTC RFC3339 밀리초 Z)을 추가한다. 이 필드를 보낸 요청은 새 경로를 사용하고, 시각 없는 기존 호출은 최초 접수 시각 기반 동작을 유지한다. 이는 기존 백엔드와의 호환성을 위한 구현 결정이다. 새 기능은 날짜 녹화 활성화가 필요하다.

## 계약

- 요청 시 설정 스냅샷으로 requested_start_at/end_at을 계산하고 준비된 녹화 범위를 고정한다. 미래 영상을 기다리거나 재요청 때 구간을 늘리지 않는다.
- 기준 시각이 미래: 400 EVENT_TIME_IN_FUTURE. 해당 시각 영상 없음: 404 RECORDING_NOT_FOUND_AT_TIME. 처리 중: 409 RECORDING_NOT_READY. 날짜 기능 꺼짐: 503 RECORDING_NOT_ENABLED.
- 기준 시각은 준비된 실제 녹화 구간에 포함돼야 한다. 중간 단절·삭제·만료 영상을 다른 영상으로 대체하지 않는다.
- coverage와 gaps, requested/actual 시작·종료 시각, event_at을 반환한다. 날짜 경계를 넘는 요청도 같은 규칙을 따른다.
- 같은 camera_id/event_id는 최초 확정 결과를 반환하며 변경된 시각·설정을 소급하지 않는다.
- 새 녹화는 1초마다 키프레임을 생성한다. 기존 10초 GOP 자료에서 허용 범위 안의 무인코딩 절단이 불가능하면 비동기 작업을 failed/RECORDING_BOUNDARY_UNAVAILABLE로 명시한다. 실제 원본 키프레임을 검사한 뒤 판정하므로 접수 후 파일 준비 단계의 오류다.
- 내보내기 동안 원본 날짜 자료를 보존한다. 사용자 삭제는 진행 중이면 409, 만료 정리는 작업 완료까지 보류한다. 재시작·실패·취소 시 보존을 해제한다.
- 구간 추출의 MP4도 기존 목록·파일 Range·삭제·보관 기간 API를 사용한다. 준비는 비동기 202, 중복은 200이다.

## 검증

기준/과거/미래/중간 누락/처리 중/잘못된 시간/동일 이벤트/날짜 경계/삭제 경쟁/재시작을 테스트한다. 실제 FFmpeg로 TS를 만들고 부분 절단 결과를 디코딩해 길이·코덱·경계 오차를 확인한다. 최종 전체 pytest와 Ruff를 실행한다. 서버 배포와 실제 백엔드 통합은 이 로컬 변경 검증에 포함하지 않는다.
